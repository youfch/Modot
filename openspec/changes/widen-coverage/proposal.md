# 拓宽测试覆盖

## Why

`cover-load-lifecycle` 把加载生命周期的每段都配上了载体，但那次覆盖评估同时列出了若干**生命周期之外**的空缺，其中一些是常见用法的**主路径**。

承接这些缺口是有依据的，不是凑覆盖率：本项目沿"扩覆盖找缺陷"这条路已连续查出 6 个真实缺陷（5 个已修、1 个待处理），其中最近一个是 `NodeReplacePatch` —— 它对任何实际用法都抛异常，**从未可用**，而它在缺少这类覆盖时一直只是"没人碰过的代码"。

本变更同时把这批工作中**已完成**的四项**补记入流程**：它们此前只在对话里被识别与批准，没有任何变更记录，因此查不到来源。

| 缺口 | 状态 |
|---|---|
| `Dependencies` 的**满足态** —— 此前只测缺失态，主路径零覆盖 | ✅ 已完成 |
| `NodeReplacePatch` 只靠文档、未被测试钉住 | ✅ 已完成 |
| `Mod.xml` 边界形态（缺必填项 / 未知元素 / XML 语法错误） | ✅ 已完成 |
| 多文件 `Data/` 的**合并**语义 | ✅ 已完成 |
| `GDLogger` 自身行为 | 待做 |
| `Node` 序列化 | 待做 |

## What Changes

- **补记**已完成的四项为任务，各自写明载体与实测结论
- **`GDLogger`**：补其 `Write` / `Error` 与惰性文件写入的行为，并据此**修正既有变更 `own-dependency-tree` 任务 7.4 的前提**
- **`Node` 序列化**：在引擎里构造节点树做往返，并把不支持的形态写成边界断言

## Impact

- 单测层 13 → 16 条；e2e 场景 19 → 21 个
- **无产品行为变更**（只加测试）
- **一处任务前提修正**：`own-dependency-tree` 的任务 7.4 要求覆盖"日志器的 `EntryWritten` 事件" —— **该成员在 vendor 的 GDLogger 里不存在**。其公开面是 `Write`、`Error(string)`、`Error(Exception)`、`Entry`、`MessageSeverity`。该任务若不改表述就无法完成，本变更在 `tasks.md` 里把它记为第一步
- 无公共 API 变更，无 `BREAKING`
